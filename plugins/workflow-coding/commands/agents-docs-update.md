# Agent Docs Update

Bring this project's documentation in line with the staged diff. The work is the `docs-sync` agent's: this command spawns it, waits for its report, and shows it. It never commits or pushes; it stops at staging. Run it on its own as a checkpoint; `/smart-commit` runs the same agent before it commits.

The `allowed-tools` above are the agent's: a command's grant reaches the agents it spawns, so under it the agent's edits, `git add` and build run without a prompt.

**Phrase each command so `allowed-tools` matches it.** Run `git` in the repository as `git <subcommand>`, never `git -C <path>`: the session already runs in the repository, and a permission matches the plain form only, so `git -C <path> status` is refused where `git status` is granted. Run every command alone, one `Bash` call each, with nothing chained (`;`, `&&`), piped (`|`) or appended (`2>&1`): Claude Code checks each part of a chain on its own, and one part not granted, a `git -C` or a read outside the repository, makes it prompt for the whole command, or refuse it in a headless run, and hides which part it was. Read a file with `Read`, not by piping it through `head`.

## The layout it keeps

- `AGENTS.md` at the root, and `<component>/AGENTS.md` in a monorepo, are hand-authored: present tense, no dates, 200 lines or fewer. Every agent loads one at session start.
- `docs/agents/[<path>/]<guide>/AGENTS.md` is a guide that one agent, or several, reads first. `docs/agents/docs-sync/AGENTS.md` is this agent's, which you write and it does not.
- `docs/agents/_history/` holds dated prose, never loaded at session start.
- `AGENTS.override.md` is generated by `/agents-docs-build` from `docs/agents/[<path>/]codex-review/AGENTS.md`.

A repository still in the old dispatcher layout (`docs/agents/core.md`, `codex.md`) is not synced: the agent says so, and `/agents-docs-migrate` moves it.

## Step 1: Spawn the agent

Use the `Agent` tool once, with `subagent_type` `workflow-coding:docs-sync`, and give it this task: bring the docs in line with the staged diff, considering these extra paths too: `$ARGUMENTS` (none if that is empty).

Act only on its hand-back: if it runs in the background, wait for its report before doing anything else. Do not edit, stage or build anything yourself.

## Step 2: Report

Show the agent's four lines (`edited:`, `rebuilt:`, `status:`, `notes:`) verbatim, except that each path in `edited:` and `rebuilt:` is written from the repository root. If it stopped, on nothing staged or on the dispatcher layout, say which.

Do not commit or push. The caller, you or `/smart-commit`, decides what happens next.
