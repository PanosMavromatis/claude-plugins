## Preamble

R2 is the subagent refactor's documentation step (§7 of `tmp/subagent-refactor-plan.md`). It does four things:

- It gives `workflow-coding` three documentation agents: `docs-sync`, `docs-classifier` and `pr-drafter`.
- `/agents-docs-migrate` moves consumers from the `CLAUDE.md` dispatcher to a hand-authored `AGENTS.md`, and the generated files shrink to the `AGENTS.override.md` pair.
- It adds `/smart-compact`, with a re-anchor hook that runs after every compaction, and `/memory-check`, which measures what the plans feed a session.
- It releases `0.11.0`.

R2 also carries R1a's two follow-ups: an end-to-end check of the pointers `fix/command-phrasing` reworded, and the close stamp's index-line form. It also carries the notes the R1 → R1a handoff set aside for R2.

R2 runs on the installed 0.10.1, not the 0.10.0 its design heading names. Its step 0, flipping the root plan to a revisions index, was done when R1a opened. Opening R2 with `/master-plan` is the last part of D8.

R2 does not move commands to skills (D6: that is R3). It does not turn the plugin's own `CLAUDE.md` into `AGENTS.md`, which waits until R2's `docs-sync` is the installed driver (R3). It does not change `dp-compile` (R4). A hook it changes is not live in this repository until 0.11.0 is installed.

## Settled decisions

- (R1a) R2 keeps `0.11.0`.
- (R1a) **Coupling with `/smart-compact` is decided in R2, by measurement**, not now. Build the handoff in R1a with `/smart-compact`'s three parts (§4.4: Keep / Drop / Say where), so R2 can reuse it rather than move it. Candidate measure: the next session's reorientation cost (Reads and tokens before the first productive action; facts the user restates).
- (D1) The "Current state" narrative moves **verbatim** to `docs/agents/_history/<area>.md`, append-only, never loaded at start.
- (D6) Keep `commands/` through R1–R2; migrate to `skills/` in R3.
- (D9) `plugin.json` gains `version`: `workflow-coding` (renamed from `workflow-claude` at 0.10.0, D-N8) 1.0.0 at R3, `dp-compile` 0.5.0 at R4; legacy single-file plans and the legacy single master plan supported through 1.x.
- (D10) `CLAUDE.md` is abolished in favour of a hand-authored root `AGENTS.md` and per-subagent guides under `docs/agents/<guide>/AGENTS.md`; `/agents-docs-migrate` performs the move.
- (D-N4) **`AGENTS.override.md` stays generated** from `docs/agents/codex-review/AGENTS.md`. The Codex CLI honours the filename regardless of how the review plugin launches it, and the build pair costs nothing.
- (D-N5) **The `SessionStart(compact)` re-anchor hook ships, on by default.** It is the one piece of the plugin that acts without a command, and it is the safety net for the case that matters most — an unplanned auto-compaction mid-goal. It is read-only, deterministic, and prints ≈ 10 lines from disk (§4.4 step 4).
- (D-N6) **Native `AGENTS.md` is the target (Claude Code ≥ 2.1.277)**; `/agents-docs-migrate` writes the two-line `@AGENTS.md` shim `CLAUDE.md` only when it detects an older version or a personal `CLAUDE.local.md`.
- (D-N7) **`memory: project` is enabled on `docs-sync` and `pr-drafter`**; `.claude/agent-memory/` is committed. The R2 test records which directory name the harness actually uses for a plugin agent.
- (D-N9) **`/new-branch` runs `/smart-compact` before anything else**, so each branch starts from pointers to the plans rather than the last branch's transcript. The user may also run it by hand mid-branch. `/step` and `/hitl-step` only *suggest* it in Step 6 (§4.4): compacting between goals would drop context the next goal in the same branch builds on, each run costs a flush pass over the conversation, and an unplanned compaction mid-goal is already covered by the re-anchor hook (D-N5).
