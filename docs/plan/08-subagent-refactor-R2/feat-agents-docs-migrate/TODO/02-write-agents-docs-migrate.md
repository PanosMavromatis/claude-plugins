**Goal**: [~]
> **Q:** Who writes the destination files, and how many scripts are there?
> **A:** A: one Python script, `scripts/migrate-agents-docs.py`, in four modes: `detect` (read-only: each target's state, sources, `codex.md` and `CLAUDE.local.md`), `check <reply>` (read-only: the table's grammar and coverage, the rule flags, `AGENTS.md`'s size), `apply <reply>` (after Checkpoint 1: copies each row's line range byte for byte into its destination, and moves each `codex.md` whole) and `verify <reply>` (read-only: the check before the destructive step). Its suite is `dev/agents-docs-migrate/`, with mutants. The destructive step stays outside the script, a `git rm` left out of `allowed-tools` so that it prompts, as `/agents-docs-init`'s heredoc did; that is goal 03's.
> **Q:** Does `apply` write anything that is not moved text?
> **A:** A: two fixed templates, which the script fills and the model never writes: a `# <name>` title on each new guide or `_history/` file, and a closing `## Guides and history` section in each `AGENTS.md` it writes, one `` - `<path>` `` line per such file. `verify` knows those lines and does not count them as source text, and Checkpoint 2 marks them as generated.
> **Note:** A dispatcher layout's `AGENTS.md` opens `<!-- Generated from docs/agents/core.md.` (pfsmgraph's does), so `detect` tells it from a hand-authored one. `apply` replaces a generated `AGENTS.md`, a copy of a source being migrated, and appends to any other file that exists, never overwriting it.
> **Q:** What does each pointer line in `AGENTS.md` say, given that run c2 moved ≈ 22.7k tokens into guides no agent reads?

The script still fills it and the model writes none of it. This amends Q2's path-only line.
> **Q:** How does `apply` handle relative links, given that all 40 in pfsmgraph's `core.md`, `claude.md` and `codex.md` would break if moved byte for byte?
> **A:** A: it rewrites each relative inline link, image and reference definition for its new location, resolving it against the source's folder and re-expressing it from the destination's, anchors kept; URLs, `#anchors` and absolute paths are left alone. A link to a source being deleted is re-pointed, `core.md` or `claude.md` to its target's `AGENTS.md` and `codex.md` to its `codex-review/` guide, and Checkpoint 2 lists each one. `codex.md`'s move gets the same rewrite. `verify` applies the same function before it compares, and checks that every relative link in a written file resolves.
> **Q:** What may a pointer line say, given that a row with no heading lent it docs-classifier's own `what` cell?
> **A:** A: only the moved text's own headings, verbatim, the first of each row's shallowest; a file none of whose rows has one gets its path alone. Every byte of `AGENTS.md` is then moved source text, a fixed template or a rewritten link. This corrects the answer above, whose "the model writes none of it" was false for the `what` fallback: on pfsmgraph that text was most of a ≈ 990-token list, written by the agent while it read sources it is told not to trust.
> **Q:** Which broken links stop the destructive step?
> **A:** A: only the links the move broke, each of which resolved from its source's folder and does not from the file it was written to. A link already dead in its source is listed at Checkpoint 2 and blocks nothing, and text that was already in a file `apply` appended to is not checked, since the migration did not write it. pfsmgraph's 40 links all resolve today.
