# /agents-docs-init

One-time migration: move content from `CLAUDE.md` into the split sources used by `dev/build-agents-md.sh`, then replace `CLAUDE.md` with a minimal `@import` dispatcher.

This is an interactive, destructive operation. Stop at each confirmation point and wait for the user before proceeding.

## Preflight

1. **Check git status.** Run `git status --porcelain`. If output is non-empty, stop and tell the user to commit or stash first. The recovery path for this command is `git restore CLAUDE.md docs/agents/`, which only works from a clean baseline.
2. **Check `CLAUDE.md` exists** at the repo root. If not, stop — nothing to migrate.
3. **Check whether migration has already run.** If `CLAUDE.md` consists primarily of `@import` directives and an HTML comment (no substantive prose), report that the migration appears to already be done and stop.
4. **Ensure `docs/agents/` exists.** Create if missing.

## Classification

Read `CLAUDE.md` in full. Partition each section (typically a heading and its contents) into one of two destinations:

- **`docs/agents/core.md`** — tool-agnostic content. Project overview, architecture, module responsibilities, build/test/lint commands, coding conventions, domain invariants, general gotchas. Anything equally relevant to Codex, Cursor, Jules, or any other agent reading this codebase.
- **`docs/agents/claude.md`** — Claude-Code-specific content. Skill references (`.claude/skills/`), slash command references, subagent or `context: fork` patterns, `/compact` instructions, MEMORY.md references, `@import` conventions, or anything that names Claude Code features by name.

If a section mixes both concerns, split it at the paragraph or bullet level. When uncertain, default to `core.md` — shared content has broader reach and the cost of over-sharing is low.

Do **not** modify `docs/agents/codex.md`. It has its own scope and is not a target of this migration.

## Checkpoint 1 — show the plan

Before writing anything, present the user with:

- A table or list of each top-level section in `CLAUDE.md` and its proposed destination (`core.md`, `claude.md`, or `split`).
- Any sections you are uncertain about, explicitly flagged.

Wait for confirmation. If the user wants reclassification, adjust and re-show.

## Writing the split

If `docs/agents/core.md` or `docs/agents/claude.md` already exists, **append-merge** rather than overwrite:

- Read the existing file first.
- For each incoming section, check whether a semantically equivalent section already exists (same heading, or same topic under a different heading).
  - If yes: merge new bullets or paragraphs under the existing heading. Skip items already present verbatim or near-verbatim.
  - If no: add the section at a position consistent with the file's existing structure.
- Preserve existing content verbatim. The goal is to add, not to refactor what's already there.

If a target file does not exist, create it with the classified content.

## Checkpoint 2 — show the resulting files

Show the user the full contents of the new or updated `core.md` and `claude.md` (or diffs if they pre-existed). Wait for confirmation that the split looks right.

## Replacing CLAUDE.md

Only after confirmation, replace `CLAUDE.md` at the repo root with exactly this content:

```markdown
<!-- Claude Code context dispatcher. Hand-authored (not a generated artifact).

     DO NOT EDIT this file directly. It is an @import dispatcher.
     - Shared project knowledge  → docs/agents/core.md
     - Claude-Code-specific      → docs/agents/claude.md

     The same sources feed AGENTS.md and AGENTS.override.md via
     dev/build-agents-md.sh. A PreToolUse hook at
     .claude/hooks/protect-agent-docs.py blocks direct writes to this file. -->

@docs/agents/core.md
@docs/agents/claude.md
```

## Checkpoint 3 — final report

Print a summary:

- Line counts of the new or updated `core.md` and `claude.md`.
- Any sections that were ambiguous and the classification decision made for each.
- A reminder to run `dev/build-agents-md.sh` and inspect the generated `AGENTS.md` and `AGENTS.override.md` before committing.
- A reminder that `git restore CLAUDE.md docs/agents/` will undo the migration if anything looks wrong.

## Do not

- Run `dev/build-agents-md.sh` automatically — the user should inspect the split first.
- Modify `docs/agents/codex.md`.
- Rewrite or "clean up" existing content in target files. Add only.
- Commit anything. The user reviews and commits manually.
